## 写新工单时请遵守的约定

1. **自包含**：新 agent 看不到你的会话。现场 IP/MAC、固件版本、文件路径、命令都要写全。
2. **先读清单要短**：只列真正必要的文件，明确写"不要通读 `project-workflow/` 与 `docs/history/`"。
3. **给出完成判据**，而且要能用命令或读数验证，不要写"确保功能正常"这类话。
4. **明确"不要做"**：本仓库的固定红线是——固件只构建 `zectrix-note4-b`、不要交替构建、不要用 `git stash`、
   不要提交密钥、后台进程分离启动且日志进 `artifacts/`、未经用户要求不提交 git。
5. **区分证据等级**：源码里有 / 已构建 / 已刷机 / 已实机验证是四件不同的事，写清楚你处在哪一级。
6. **不要用旧文档当事实**：这个仓库多次出现"文档说没做、其实已经做了"。落笔前用 `git log -S`、
   产物时间戳或直接读代码核实一遍。
