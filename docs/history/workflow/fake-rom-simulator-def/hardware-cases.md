# D/E/F 边界外的硬件错误 case（仅文档）

范围：以下只记录 Fake ROM 无法证明的硬件行为；不实现夹具、不执行实机测试，也不恢复 G 整套回归。若 D/E/F 的软件协议 case 已覆盖同一错误，不重复增加硬件 case。

| Case | Fake ROM 无法覆盖的错误 | 条件与观察点 | 判定 |
|---|---|---|---|
| H01 | Windows 在 GATT 特征表变化后继续使用缓存的旧属性 | 固件的特征表确实变化且旧配对记录仍存在时，记录发现的服务/特征 UUID、订阅与写入的实际结果，以及解除配对重配后的差异 | 不能把旧缓存导致的服务缺失误判为 fake BLE 协议失败；重配后能按新表建立会合 |
| H02 | 面板 BUSY/LUT 或残影导致屏幕实物与帧缓冲不同 | 实际显示提交与局刷完成时，记录 BUSY 释放、实物画面和 `/status.json` 的显示状态；覆盖一次失败后恢复全刷 | Fake ROM 的帧 CRC 只证明软件像素和提交顺序，不能替代面板实物一致性 |
| H03 | Flash/RTC 在真实掉电或棕断中的保留边界与宿主文件模型不同 | 在真实断电边界记录重启原因、A/B metadata/active context、RTC checkpoint 与设备自报 job/seq；对照 D2 的短写和进程 kill 结果 | 只接受完整合法 Bundle；不得出现幽灵 ACK、旧 context 复用或把 RAM/RTC 保留误认为 Flash 持久 |

这些 case 只在遇到相应硬件特有错误时作为排查记录使用。执行与结论不属于当前 D/E/F 交付。
