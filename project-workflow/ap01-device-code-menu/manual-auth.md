# AP01 手动接口设备码鉴权

2026-10-22，06已部署应用槽1并实机验证菜单码维护、切槽/重启及独立救援回切；救援槽0未写，完整非活动镜像SHA保持不变。当前八位码重启后保持，原Bridge凭据及业务兼容。证据见 [status.md](status.md)，现场部署以 PROGRESS.md 为准。

在原厂“设置 → 设备码”查看八位数字，在维护端口18080发送 `Authorization: Bearer <八位设备码>`。前导零必须保留；不把设备码放进URL或请求正文。

| 接口 | 凭据及行为 |
| --- | --- |
| `GET/PUT /api/wifi/profiles` | 当前八位码；沿用MAC、revision及原有字段校验。仅管理列表，不切网。 |
| `/api/diagnostic/status`、`/file`、`/flash` | 当前八位码；沿用方法、MAC、范围、忙状态及路径校验。 |
| 日常业务18081、配对、claim、模板发布和数据同步 | 原Bridge绑定密钥及原有身份/owner校验，无新增输入。 |
| 应用ROM `/api/firmware/*`、`/health`、`/api/maintenance/status` | 当前八位码或原Bridge绑定密钥；无绑定时八位码可独立完成OTA、回执查询、重启及切槽，不需要业务owner。 |
| 0031救援ROM独立OTA及原厂恢复通道 | 仍使用原有凭据；本次不改救援ROM。 |

手动Wi-Fi/诊断接口不接受Bridge密钥；应用固件维护保留Bridge密钥兼容。八位码不能用于日常业务、配对或claim。每次八位码请求仅读取已提交设备码，不自动创建、不缓存授权。菜单明确重新生成后，后续请求必须使用新码；已获准的在途操作按原事务完成，不自动取消或重发。新的当前码可查询或继续同一个本地维护事务，不换ID重发；绑定Bridge发起的事务仍保留原principal围栏。重启不更换设备码。

缺码或错码返回401/`manual_auth`，提示输入当前菜单码。设备码未创建、损坏、读取失败或提交状态未知时返回503并提示打开菜单；读取异常不会触发自动重置。每连续五次凭据失败后，手动接口暂停30秒并返回429；限制只保存在当前应用实例RAM中，重启清除，日常Bridge及固件恢复不受影响。重复Authorization等解析错误仍明确拒绝。

持久格式仍为16字节DVC1，临时提交额外16字节；本次不增加持久字段。原生Runtime/Business/Store大小不变，Application增加24字节用于读取回调和有界失败状态。原生模拟不是物理LCD、熵源或完整调用链栈峰值证明。
