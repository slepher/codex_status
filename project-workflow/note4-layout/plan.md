# Note4 模板布局与唤醒图标修复

2026-09-29。用户实机反馈：先前按 1/2/3 位分别手调坐标的预览未成为可发布模板；唤醒后 Wi-Fi 图标未闪烁；Bridge OFF 图标看起来是 ON 叠斜杠。

## 已核实

- 当前模板只支持 `when.exists` / `when.equals`，不能按余量位数选择 `%` 坐标。此前离线预览是三份不同 JSON，未保存到 Bridge。
- 当前固件仅在 `connectBest` 内、且已有可信局刷基线时每 1 秒尝试切换 Wi-Fi 图标；连接短于 1 秒或屏幕基线不可信时不会发生一次闪烁。设备诊断还记录过局刷失败，不能以模板像素预览证明实机闪烁。
- Bridge 图标的 `device.offline_mins` 条件与 `device.state` 条件可同时成立，于是两种 20×20 glyph 在同一位置叠画。
- 实机后续纠正：休眠转唤醒、Wi-Fi 连接尚未判定期间，Bridge 图标必须沿用休眠前的 ON/OFF；仅连接尝试结束后由 ROM 更新状态。模板继续只按 `device.offline_mins` 画 ON/OFF，不增加状态机。

## 执行顺序

1. 确认用户所说闪烁覆盖的时间窗口；修正固件中的状态/刷新时序，并用日志和真实屏幕验证。
2. 给文字元素增加 `digit_bind` + `digit_x` 三个位数坐标，固件、Bridge canonical 校验与宿主渲染保持一致。它使用 ABI 2 中文字操作未占用的字段，避免全平台 ABI 升级影响 1.54；Bridge 发布时以模板的 `min_fw` 阻止旧 Note4 ROM 接收。验证边界值 0、9、10、99、100 与 5h 缺失分支。
3. 让 Bridge OFF 图标的条件互斥，核对 OFF 与 ON 各自独立的像素。
4. 先产出可审查的单份模板与 1/2/3 位预览，再构建/校验 Note4 ROM。固件更新是新条件的部署前提，设备发布前需核对 ROM、MAC、版本与哈希；模板保存/发布为显式步骤。
5. 实机核查：认证 Bundle ACK、刷新状态、Wi-Fi 连续亮/空白、Bridge OFF glyph，以及屏幕实际布局。仅凭作业 succeeded 不宣称屏幕正确。

不触碰 1.54 目标或其他用户未提交改动。
