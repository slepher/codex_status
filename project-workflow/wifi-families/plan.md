# Wi-Fi 族（2026-10-26）

Bridge 维护共享族库：稳定 ID、族名（缺省 5G SSID，其次 2.4G SSID）、2.4G/5G SSID 及各自凭据；同名双频允许。各设备独立选择一个或多个族。Note/BW 复用现有 host_ssid 字段表达族名，设备协议及 WFS4/WTX1 不变。主机任一族内 SSID 解析为族名；无 Wi-Fi 时允许指定族，未知/歧义不猜测。

AP01 使用既有维护列表接口及菜单八位码，只同步兼容列表，保持旋钮手选；不修改兄弟仓库系统实现或鉴权。设备回读仍走现有读取/比较/显式导入流程，无法判定族的新条目需人工归属。

实现顺序：共享模型/原子持久与选择投影；自动路径族解析/环境变化检查；共享 UI/MCP 入口及 AP01 列表适配；回归和边界记录。不停运行桥、不改真实凭据、不刷机、不提交。


## 使用入口

设备页的“Bridge 方案”直接管理共享族与设备订阅；“新增共享族”或“编辑族”展开唯一编辑器：填写2.4G/5G SSID及凭据，族名留空默认5G SSID（无5G则2.4G）。同名双频两栏填写相同SSID及密码。共享库编辑更新所有订阅设备的Bridge目标，但不写设备。

在各设备页勾选一个或多个族并保存同步范围；读取设备完整方案后，在原“比较与同步”页选择条目、预览和提交。取消订阅只移除Bridge目标，不删除设备已存网络。旧记录不自动迁移或猜分组；明确订阅可接管相同旧映射，冲突保留并提示。

主机任一族内SSID识别为该族；无Wi-Fi时使用“主机使用有线网络时的族”。未知Wi-Fi、权限不足、歧义不使用手选族冒充当前环境。

已订阅的族通过原设备→Bridge导入更新共享库；尚未归属的设备条目，在比较页选择一条，再明确选择目标族并导入共享库；普通整条导入只用于已关联族，不再新建隐藏的单设备目标。AP01读取不提供密码，跨设备下发所需密码必须在共享库补齐，不能用空值冒充已读凭据。

AP01读取/同步前输入设备“设置→设备码”的八位码，每次请求后清空。只更新列表，不发送切网。结果未知时先读回原操作；仅在人工检查后，可明确接受当前读回列表并解除阻挡，记录仍说明原操作/密码未知，不重发原保存。


## 2026-10-27 用户授权合并旧网络

从当前Bridge已保存目标及完整缓存快照提取，不读私有日志找密码、不重新获取设备凭据。按主机SSID→设备SSID及相同设备SSID去重，密码冲突明拒；共识别3族：两族有不同主机/设备SSID，其中一族主机5GHz有本机BSS证据，另一族按明确5G命名及已有映射归类；第三族仅有2.4G设备记录，5G不猜测。已有密码原样保留，独立5G密码没有缓存则保持未知，不用2.4G密码冒充。

保留旧范围：Note4三族、BW仅原来的一族；AP01没有旧Bridge网络快照，不代其新增订阅或改手选列表。先停默认Bridge并完整备份，使用一次性Rust助手调用现有PlatformService库保存/验证/原子投影，保持设备快照/原事务/Profile/许可不变，随后按规定脚本重启并只读验证。无需改ROM或重新构建Bridge。

后续用户明确：第三族是同名双频，三个设备均只支持2.4G。族库记录双频可用性用于识别主机环境，所有设备映射始终选择2.4G；相同SSID共享原凭据，设备订阅范围不变。
