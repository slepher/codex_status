# 设备页与 MCP 读取合同

日期：2026-09-29。状态：**共享主视图与按 MAC 栏目查询已实施、已部署；时间语义源码已按 `device-page-time-plan.md` 收束，运行版已核验；完整 U01–U20 待验**。设备页的内容与顺序以同目录 `device-page-content-contract.md` 为准；本文件记录 MCP 对等要求。运行版证据见 `PROGRESS.md` 最新节，待办以 `docs/roadmap/backlog.md` C8 为准。

## 1. 一条原则

**用户在设备页默认能看到什么，MCP 的默认设备查询就返回什么。**两者使用同一份按 MAC 隔离的 Bridge 状态和同一套结论，不各自解释 OTA、显示、连接或采样年龄。返回结构化值、用户可读结论及证据时间；无需复制 HTML 文案或 DOM 结构。

设备页默认折叠的内容不夹带在默认 MCP 结果里。MCP 通过**独立的只读详情查询**，由调用者指定设备 MAC 和折叠栏目，按需取得该栏目内容。详情查询不因读取而向设备发请求。现有显式 `platform_status_refresh`、`pm_stats` 等采样动作与缓存查询分开，且必须准确说明它们可能失败或扰动设备。

## 2. 默认设备视图

默认查询先给已登记设备列表（名称、MAC/型号、该设备的简短状态与待处理提示）；指定 MAC 后给与设备页当前主视图相同的内容。多设备时不从 Bridge 的全局默认设备猜测用户选择；每条结果和每个后续操作都明确 MAC。名称只是可重名的本地标签，MAC 是身份。

| 主视图信息 | 返回和展示口径 |
|---|---|
| 设备联系 | 最近认证联系的时间/通道、预计休眠或连接受阻。发现到 IP、收到 BLE 会合、完成 Wi-Fi 认证分别表示不同事实；深睡时的 HTTP 超时不等于设备故障或“当前离线”。 |
| 固件升级 | 设备最近一次完整 Wi-Fi 回报的**当前版本及公共回报时间**；按该设备 firmware target 显式登记的**最新可用版本**；比较结论为“已是最新版”“可升级”或“无法判断”。未采样设备或未登记发布版时不得猜。两侧具备可比的运行镜像哈希时，同版本不同字节不能报“最新版”。 |
| 最近升级失败 | 仅当当前运行结果与最新可用版本有差异，且该设备最近一次相关推送确实失败时，在主视图显示最近一次失败及可理解的原因。旧任务的上传 ACK、`awaiting_confirmation`、`version_seen_unproven`、arm/ticket/409 原文不作为主状态。 |
| 屏幕结果 | 设备实际报告的已安装/active 内容与显示结果。区分“已提交或已安装”“数据已应用”“屏幕已显示”和“显示失败”；只读观察不等于模板编辑或发布入口。 |
| 电量与数据投递 | 电量继承公共完整 Wi-Fi 回报时间；数据投递许可是 Bridge 设置，不称设备采样。许可只控制业务数据，不关闭状态/诊断同步；保存许可不发布 Bundle。 |
| 连接与占用 | 当前已知的设备名称、占用结论及其观察时间；IP 只是连接线索。未知 owner 不写成空闲，采样时 Wi-Fi/BLE 连接不写成此刻在线。 |
| 需要处理的事 | 有新版、最近相关升级失败、设备报告显示失败、身份或占用受阻等用户可处理结果。单次探测失败和正常休眠不自动升级为主警报。 |

默认视图提供一次完整 Wi-Fi 回报时间及最近认证联系时间/通道；同次回报的字段继承公共时间，不逐项重复 `observed_at`。仅不同来源或旧回报字段给出字段级时间例外；Bridge 事件使用准确的事件时间名称。各字段仍保留“尚未采样/本次读取失败/固件不支持/不适用”原因。旧值不能因新的 BLE 联系或页面刷新变新；无可信观察时不显示肯定的“最新版”或“显示成功”。详见 `device-page-time-plan.md`。

## 3. 默认折叠栏目：单独查询

MCP 按栏目获取；可以用一个带 `section` 参数的只读工具，但一次只返回请求的栏目，不提供隐式 `all`。默认设备查询不预加载这些字段。

| 栏目 | 按需返回内容 |
|---|---|
| `firmware` | firmware/render target、ABI、运行槽位、重置原因、运行镜像证据；同次完整回报共用时间，独立镜像核验另记核验时间。登记的兼容性标签与 OTA 镜像证明分开。 |
| `connection` | 完整 MAC/IP、发现方式与时间、Wi-Fi/RSSI/BLE 的采样时状态、owner/lease 的观察值。 |
| `runtime_display` | heap、uptime、EPD 写入与 busy 失败、已安装模板 ID、active context、commit 序号及显示诊断。 |
| `sync_diagnostics` | 15 轮计数、due/phase、当前批次/ACK/complete、最近完整归档、缺口、环形日志与历史合并后的诊断摘要；原始记录另按现有诊断读取能力处理，不在默认视图倾倒。 |
| `power` | 正式 PowerPlan 的发送/ACK 事件时间及各自剩余观察值、provisional；整块 PM 统计共用一次成功采样时间，失败尝试另记。没有 boot 身份的旧 PM 样本不能无条件称“本次启动”。显式 PM 采样仍是另一动作。 |
| `upgrade_history` | 该 MAC 的升级历史归档：版本、target、时间、最终结果、失败或关闭原因，并保留 job ID、上传 ACK 和镜像证据供追查。历史任务不得反向覆盖当前固件结论。Bundle 历史与设备安装/显示结果也须保持区分。 |
| `maintenance` | 恢复 Profile 等高级操作所需的只读前置信息；执行恢复、claim、发布、OTA 等动作继续使用各自显式工具，不由详情读取触发。 |

页面后来增加或删除默认折叠栏目时，同步调整 MCP 详情栏目；不能出现 UI 已折叠但默认 MCP 仍一次返回大段内部状态，或 UI 主区有结论而 MCP 默认查询拿不到。

## 4. 接口与状态边界

- 已有 `platform_device_view` 主视图只读查询和 `platform_device_detail(mac, section)` 折叠栏目只读查询；本轮调整它们的共享时间投影。`platform_overview` 仍是简表，`firmware_ota_status` 仍是原始当前任务，均不冒充主视图。
- UI 与 MCP 应从共享 application service 获取同一投影和结论。MCP 默认结果不能通过额外调用设备 HTTP、BLE 或 PM 接口凑齐；显式刷新后，两端再读取同一更新后的缓存。
- 主视图返回用户可读状态及必要的结构化字段。任务中间态、原始协议错误、哈希、批次 ID、计数器放对应详情或历史；诊断数据仍可追溯，不丢证据。
- 设备 A 的缓存、发布版、OTA 历史、错误和采样时间不能进入设备 B；切换 MAC 不能把 A 的旧结果标成 B 的当前状态。
- 版本相同、版本不同、无发布版、无认证样本、同版本不同镜像、最近推送失败但已运行最新版、深睡旧样本、显示安装成功但屏幕失败，均需验证 UI 与 MCP 默认查询的结论一致；折叠详情只在单独查询中出现。

## 5. 当前实现与剩余验收

`platform_device_view` 不带 MAC 时只列登记设备简况，指定 MAC 时返回与设备页默认主区相同的投影；`platform_device_detail` 按 MAC 和单个 section 读取折叠栏目。两者只读 Bridge 本地状态，显式 `platform_status_refresh` 仍负责设备采样。默认 Bridge 已部署这两个入口，双设备运行查询和七个栏目逐一通过；时间去重与来源例外已在共享投影实施，运行版结果见 `PROGRESS.md` 最新节。完整 U01–U20、最终窗口视觉和部分诊断详情产品验收仍见 backlog C8，不能从局部运行查询推定全矩阵通过。
