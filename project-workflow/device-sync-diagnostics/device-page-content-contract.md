# 设备页内容与信息层级

日期：2026-09-29。状态：**主视图与折叠结构已实施、已部署；时间显示源码已按 `device-page-time-plan.md` 收束，运行版已核验；完整 U01–U20 与最终窗口视觉待验**。这是设备 Tab 的产品合同；实际证据见 `PROGRESS.md` 最新节，后续待办仍从 `docs/roadmap/backlog.md` C8 跟踪。MCP 对等要求见 `device-page-mcp-contract.md`。

## 1. 设备页回答的问题

用户打开设备页，应依次得到：**选中的是哪台设备、最近是否正常联系、当前运行什么版本及是否有新版、屏幕实际显示是否成功、是否有需要处理的失败**。之后才查看电量、连接、投递许可、维护和诊断。主视图显示设备的最终运行结果，历史任务与协议中间步骤进入归档/详情。

设备页信息始终以选中设备的 Wi-Fi MAC 为作用域。多设备不共享任务、错误、采样时间、owner 或电源计划；切换时不残留上一台数据。设备休眠是预期运行状态，不能仅凭一次 HTTP 不可达判故障。

## 2. 默认展开的内容与顺序

| 顺序 | 内容 | 用户应看到的结论 |
|---|---|---|
| 1 | 设备选择与身份 | 名称、型号或固件 target 的易读名称、该设备的简短状态；完整 MAC/IP 可在连接详情查看。名称可重名，MAC 是身份。 |
| 2 | 设备状态 | 上次完整 Wi-Fi 状态回报的时间；最近认证联系若是之后的 BLE 会合才单独显示联系时间和通道。预计休眠/最近已认证/认证或占用受阻分别说明，BLE 联系不更新旧 Wi-Fi 值。 |
| 3 | 固件与升级 | **当前版本、最新可用版本、结论**。相同为“已是最新版”，不同为“可升级”；版本未知或没有按 target 登记的发布版时写“无法判断”，不从最近 job、文件名或版本字符串排序猜测。当前版本继承完整 Wi-Fi 回报时间，不另给固件栏目造时间。若有可比镜像证据，同版本不同字节不可报最新版。 |
| 4 | 最近升级失败 | 仅在设备与最新可用版确有差异，且该设备最近一次相关推送确实失败时，显示最近失败及可理解的原因。已经运行最新版后，旧失败不再占主区；去升级历史归档查看。 |
| 5 | 屏幕结果 | 设备报告的已安装、active 内容和最近显示结果。分别说清“配置已提交/安装”“数据已应用”“屏幕已显示”或“显示失败”；不能把 Bundle ACK、同步完成、Plan ACK 当成屏幕已显示。模板 ID/context/job ID 可在详情看到，不作为主标题。 |
| 6 | 设备电量与数据投递 | 电量继承其所属完整 Wi-Fi 回报时间，不在电量行重复；该设备是否允许业务数据投递是 Bridge 设置，不称设备采样。关闭投递不关闭状态/诊断同步，保存许可不发布 Bundle。采样时 Wi-Fi/RSSI 不应压过版本和屏幕结果成为顶部主指标。 |
| 7 | 连接与占用 | 易读的占用状态和观察时间；改名、重新发现、占用/释放等动作放在连接管理区。强制接管保持高级入口，明确目标设备。 |

页面只突出用户可处理的异常：有可用新版、最近相关升级失败、屏幕报告显示失败、身份/认证/占用受阻，以及持续的同步故障。普通深睡、单次读取超时、历史失败和内部待确认阶段不自动变成主警报。

## 3. 默认折叠的栏目

| 栏目 | 内容与边界 |
|---|---|
| 设备详细信息 | 固件 target/render target/ABI、运行槽位、重置原因；采样时的 Wi-Fi/RSSI/BLE 状态；heap、uptime、EPD 写入及 busy 失败；已安装模板 ID、active context、commit 序号。同一次完整状态回报共用一次时间；不同来源或旧回报字段才单独标时间，缺失原因仍逐字段保留。 |
| 升级历史归档 | 按该设备列出历次 OTA：目标版本、时间、最终运行结果、失败或关闭原因；展开单条才看 job ID、上传 ACK、镜像哈希与中间状态。旧任务不得占住当前版本/最新版本的展示，也不得仅因后来用别的方式升级就伪记原 job 成功。 |
| 发布与显示历史 | Bundle 的任务与设备安装/显示结果分开。任务“已提交”不等于屏幕“已显示”；已安装但显示失败应在主区显示故障。 |
| 同步与诊断 | 15 轮计数、due/phase、最近完整 Wi-Fi 同步、归档缺口、当前批次/ACK/complete、合并后的跨深睡诊断记录。保留原始证据，但不在主区倾倒协议字段或日志。 |
| 功耗与计划 | Bridge 已发送和设备已接受的正式 PowerPlan、采样时剩余值、provisional；本次启动的 light sleep/CPU/PM 锁统计与原始输出。明确这些数值不是整机续航或 deep sleep 占比。 |
| 恢复与维护 | 从设备恢复 Profile 等低频操作；读取详情不自动执行恢复、发布、claim、开 Wi-Fi 或改变电源计划。 |

折叠只是页面信息层级，不意味着删除数据。默认折叠的数据要能由 MCP 的独立只读接口按 MAC 和栏目获取；MCP 默认设备查询只返回本页默认展开的内容，详见 `device-page-mcp-contract.md`。

## 4. 来源、年龄和缺失

- 当前版本、运行槽位、重置原因、电量、无线、heap、EPD 等来自对应设备的认证快照；登记的 target、名称、IP 是 Bridge 的登记或发现信息，必须标明来源。屏幕结果优先使用设备实际报告，不以 Bridge 的发布意图替代。
- 一次完整 Wi-Fi 状态回报只在公共状态区显示一个接收时间，正常字段继承它。旧字段可显示为“上次观察于”，不能被新 BLE 联系、页面缓存刷新或一次失败的 Wi-Fi 探测更新年龄；Bridge 任务、登记、占用及 Plan 使用事件时间而非“设备采样”。已知新 boot 后，旧 boot 的运行与无线数值不得装作本次启动的值。完整归组和例外见 `device-page-time-plan.md`。
- 区分“尚未读取”“固件不支持”“不适用”“本次读取失败”“旧值”和确实为 `0`、`false`、空模板列表。不能用一排 `--` 或一个“离线”掩盖不同原因。
- “刷新缓存”只读 Bridge 本地记录；“从设备读取”是显式认证 Wi-Fi 请求，设备深睡时可能等下次联系。页面展示不应隐式开 Wi-Fi、扩充每轮 BLE 遥测或改变 light 计划。

## 5. 原设备页模块的处理

| 现有内容 | 处理 |
|---|---|
| Codex 用量 | 从设备页移除；数据 Tab 已有足够内容，本轮不改其排版。 |
| 屏幕内容、模板/Profile 编排、字体编辑 | 从设备页移除。只声明这些属于模板页；**模板页暂不添加，也不规划迁移布局**。保留设备页只读的实际安装、active 和显示结果。 |
| “完整认证快照”主指标 | 改为状态的采样说明，不与版本、显示结果争夺主位置。 |
| 原始 Bundle/OTA 任务行 | 主区改为设备最终结果及必要的最近失败；原任务和证据进折叠历史归档。 |
| 连接/占用与高级操作 | 保留，低于状态、固件和屏幕结果；强制接管保持折叠。 |
| 数据投递许可 | 保留为设备级设置，保存只改该 MAC 的许可。 |
| PowerPlan、PM 统计、恢复 | 保留为折叠的高级栏目，显式操作与只读查看分开。 |

## 6. 验收场景

1. 当前版本等于最新登记版时，主区显示“已是最新版”，旧失败只在历史；版本不同显示“可升级”，最近相关推送失败时同时显示最近失败。
2. 没有最新登记版、没有可信设备版本，以及同版本但运行镜像不同，都不产生虚假的“最新版”。旧样本须标“按上次回报判断”和原时间；未经产品另定期限，不凭任意 TTL 改成“无法判断”。
3. OTA 上传 ACK 后仍未证明运行结果时，主区继续以已观察的当前运行版本判断，内部确认等级仅在历史/诊断中；旧任务不会无限占主状态。
4. Bundle 安装成功但显示失败时，主区明确提示显示失败；同步归档完成不改变这一结论。
5. A/B 两台切换后，版本、失败、历史、owner、采样时间和详细信息均严格按 MAC 隔离。正常深睡与单次探测超时不被显示为硬件故障。
6. 用户默认看到的每项结论在 MCP 默认设备查询中一致；页面折叠栏目只在 MCP 的独立详情查询中返回，二者均不因普通读取主动联系设备。
