# 设备页与 MCP 时间显示收束计划

日期：2026-09-29。状态：**源码与运行版已实施；完整 U 矩阵待验**。本计划修正设备页/MCP 对等改造后的时间语义；现有 `platform_device_view`、`platform_device_detail` 和主视图已部署，不重做信息架构。执行与剩余验收以 `docs/roadmap/backlog.md` C8 为准。本文件的“采样”指设备状态回报或显式 PM 读取；Bridge 任务、发布、占用、计划及归档使用各自的**事件时间**。

## 1. 用户可见规则

正常设备页主区显示一次 **“上次完整状态回报：时间 · Wi-Fi”**。同一次认证 `/api/status` 回报的固件、电量、无线、运行、安装、数据及屏幕字段共享这一时间。Bridge 为缺失原因和缓存而建立的 `firmware/radio/runtime/display/power/...` 组，不代表设备按栏目分别采样；不得给每个值重复附“采样于”。

最近认证联系若是同一次 Wi-Fi 回报，不重复显示第二个时间；若后来有 BLE 精简会合，另显示一次 **“最近认证联系：时间 · BLE”**。它只刷新 BLE 实际携带的字段，不能使旧固件、电量、显示结果等 Wi-Fi 值变新。`device_detail(power)` 展开后，PM 统计整块只显示一次 **“PM 采样：时间”**。只有一个字段确实沿用更早回报时，该字段例外标“上次观察于”；`0`、`false`、空列表仍为有效新值。

设备页不应为了追求固定的“只有三个时间”而混同真实来源。独立的 owner 公开状态观察、运行镜像核验、Bridge 发布登记、OTA/Bundle 失败或完成、Plan 发送/ACK、归档持久完成均用准确的**观察或事件名称**及时间。缺少真实时间就显示“时间未记录”，不由文件 mtime、相近秒数或页面读取时刻推算。

## 2. 全设备页归组

| 字段或栏目 | 默认继承的时间 | 真实例外 |
|---|---|---|
| 当前固件版本、槽位、重置原因、boot、目标硬件的设备自报值 | 最近完整 Wi-Fi 回报 | 独立运行镜像前缀 SHA 查询另记“镜像核验于”；本回报省略的旧字段标上次观察 |
| 电量、Wi-Fi 连接/RSSI、BLE 采样时状态、heap、uptime、EPD 计数 | 最近完整 Wi-Fi 回报 | uptime 是采样当时的持续时间，不能随墙钟递增；已知重启后旧运行值标旧 boot |
| 已安装项、active/context、commit、数据已应用、display_state | 最近完整 Wi-Fi 回报 | BLE 精简状态实际更新的 active/context/applied_seq 可引用最近 BLE 联系；BLE 不携带的安装/显示结果保持原 Wi-Fi 时间 |
| 同步 rounds/due/phase、设备 pending/complete | 携带这些字段的 Wi-Fi 或 BLE 回报 | 必须保留来源；尚未入缓存的 BLE 字段不能在 UI/MCP 中宣称已实时更新 |
| 设备名称、MAC、Bridge 登记 target/render target/ABI、数据投递许可、恢复入口 | 不用“设备采样于” | 有保存/登记时间则在详情写“保存于/登记于”；没有则不制造时间 |
| 最新可用固件、升级结论 | 当前版本继承 Wi-Fi 回报；最新版本来自 Bridge 发布目录 | 最新版的 `published_at` 属登记事件，放固件详情；比较结论不另生“结论采样时间” |
| 最近相关升级失败、OTA/Bundle 历史 | 对应任务失败/关闭等事件时间 | 屏幕实际显示结果仍引用设备回报，不由任务时间代替 |
| 最近联系、预计休眠、认证尝试失败 | 最近真实认证联系时间/通道 | 失败单列“尝试失败于”；不覆盖最后成功回报。最近联系就是完整 Wi-Fi 回报时合并显示 |
| IP/发现方式、owner/lease、claim/release/renew | 发现、公开状态观察、操作确认各自事件 | 公开 `/status.json` owner 是另一条真实读取路径；不得冒称认证 Wi-Fi 回报或纯 Bridge 本地设置 |
| 已发送/已接受 PowerPlan、ACK 剩余、provisional | 发送与 ACK 各自事件时间；设备状态中的剩余继承该次回报 | ACK 当时的剩余与后来设备回报的剩余不能拼成同一采样；无可信依据不做实时倒计时 |
| light sleep 次数/占比、CPU 模式、PM 锁、原始文本 | 最近一次**成功的显式 PM 读取** | 失败保留旧成功样本时间，另写“最近尝试失败于”；跨重启旧 PM 样本无 boot 证据时不称“本次启动” |
| 诊断批次、ACK、归档、gap、设备日志 | 设备回报或 Bridge 传输/归档事件，各按真实来源 | 当前 `last_full_success` 是 batch ID，不是完成时间；旧记录无时间时写“时间未记录”；日志记录使用自身 boot/generation/seq/设备时钟证据 |

## 3. 最小实现组织

1. **共用投影。**在现有主视图和详情投影中提供一次完整 Wi-Fi 接收时间、最近认证联系时间/通道和必要的事件时间引用。字段默认继承公共回报；仅不同来源或保留旧值时附字段级例外。UI 与 MCP 消费同一投影，默认只读不发设备请求。
2. **准确标来源。**现有摘要接收同时处理 HTTP/BLE，却未完整保存摘要 transport。收束此来源；同一次 HTTP 处理应共用一个接收时刻，避免跨秒调用产生虚假的两次采样。不能用 BLE 样本里不存在的 fw、battery、display_state 填新值；boot 身份若要靠 `session_nonce`，先证明其语义。
3. **页面去重。**主区的普通读数格式器只渲染值与缺失原因；公共时间在状态区显示一次。折叠详情也继承同一回报时间，旧值或独立来源才标时间。时间来自未来或墙钟回退时显示异常/绝对值，不写成“刚刚”。
4. **详情对等。**PowerPlan UI 与 MCP 详情使用同一服务结果，分别暴露已有的发送/ACK/状态回报时间；PM UI 与 MCP 使用同一按 MAC 缓存和成功/尝试时间。占用要说明公开状态观察和认证/claim 缓存的不同来源，旧缓存来源未知时如实标未知。
5. **归档时间按真实事件补。**如产品需要“最近完整归档于”，仅能在真实 complete ACK 且持久提交的边界记录；历史无此字段的批次继续显示时间未记录。此项不阻塞普通状态时间去重。

## 4. 验收用例

- 一次完整 Wi-Fi 回报中的 fw/radio/power/display 等值，UI 主区只出现一个完整回报时间；MCP 主视图引用相同时间。随后 BLE 会合只增加最近联系时间，旧 Wi-Fi 值年龄不变。
- 新回报省略某字段，仅该字段标旧回报时间；`0`、`false`、`[]` 在新回报中仍判有效。BLE 可更新 active/applied 时，仅实际携带字段改变；display_state 不凭 BLE 变成成功。
- 刷新本地缓存、展开详情、设备深睡、HTTP/PM 读取失败均不改变上次成功回报时间。PM 所有指标共享其成功采样时间，失败尝试另记。
- 固件登记、OTA/Bundle 任务推进、claim/renew、Plan ACK、归档完成只改变自身事件时间，不刷新 Wi-Fi 回报。公开 owner 观察与认证快照分开。
- A→B→A、已知新 boot、同秒不同来源、墙钟回退和旧缓存来源未知时，UI 与 MCP 的来源、时间及缺失原因一致。
- 主视图不泄露折叠详情；`platform_device_detail(mac, section)` 仍按需返回对应时间证据，不隐式请求设备。

## 5. 已知边界

当前 BLE 摘要不带 fw、boot_id、display_state、电量、radio/heap；不能由模拟样本推断实机有这些字段。公开 owner 是独立设备读取路径。PM 样本缺 boot 身份，不能严格保证跨重启后仍属“本次启动”。新归档 checkpoint 在 complete 持久提交时记录时间，历史 checkpoint 无此字段仍显示时间未记录。页面对未来时间显示绝对值并标出异常。正式 PowerPlan 的真实发送时刻尚未单独持久化，当前只能准确显示生成与 ACK 时间。旧样本超过多长时间才使“已是最新版”变为“无法判断”尚无产品阈值：默认使用“按上次设备回报判断”并显示其时间，不擅自发明 TTL；若要求强制失效，须另定明确期限或失效事件。
