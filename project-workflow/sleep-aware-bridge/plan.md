# 休眠设备状态与延后操作：计划

日期：2026-09-26。阶段：实施与验收中。待办总入口仍为 `docs/roadmap/backlog.md`「Bridge 休眠设备的状态与延后操作」。本目录是该条目的实施合同，不另建待办事实来源。

## 目标与边界

设备大部分时间休眠是正常工作方式。设备页保留上次成功认证通信所得值、时间与数据年龄；显式模板发布和 OTA 先落盘，等待目标 MAC 的下一次认证通信机会。区分排队、传输、设备 ACK、重启后确认和真实失败。修复已登记设备没有 runtime record 的 Bridge 缺口，不能用「休眠」掩盖它。

复用 v2 PlatformService、Coordinator、PowerPlan 和现有传输。保存不发布；不自动唤醒、不绕过 token/claim、不让轮询或传输隐式延长 light deadline。不同 MAC 的缓存、任务、确认、错误独立。本轮实施桥与 Note4 固件源码；不刷写真实设备。

## 阶段与交付门槛

1. S1 状态合同：补全登记设备运行记录；持久最后成功快照，分离尝试结果；UI/MCP 同一返回模型。先消除截图错误和正常休眠的误报。
2. S2 持久任务：显式 OTA 入口统一至 app service；冻结镜像和 MAC，落盘后才返回 queued；复用已有发布队列，补确认与取消边界。
3. S3 会合交付：按 MAC 调度、认证对账、正式 PowerPlan、claim、事务互斥；重启恢复先确认未知结果。
4. S4 确认与呈现：发布以业务 ACK/认证状态确认；OTA 分上传 ACK、版本观察和精确镜像确认，能力不足如实说明。
5. S5 验收：故障注入和两设备测试通过后，按用户实际授权执行 Note4 构建/实机验收及更新 PROGRESS。不得把设计完成写成实现完成。
