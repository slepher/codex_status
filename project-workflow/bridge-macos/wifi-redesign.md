- 普通已绑定/加密且认证的 Bridge 在 owner 允许、MAC/会话 nonce 正确时，借用已有 formal light 或 sync 窗口写本绑定配置；BOOT 仍只用于首次绑定、物理救援和旧槽迁移。许可截止取已准入 RF/业务窗口的较短期限，不申请/续租。物理救援保持原固定截止与独立 bond 授权。
- `wifi_save` BLE 支持 1–4 条冻结整行变更，业务载荷最多4096B、MTU分片，最终 ACK/INFO 仍≤512B；和 HTTP apply 共用原子 NVS commit、expected_revision、安装身份+稳定 request_id 与持久回执。回执含提交 revision/bond，不含密码。结果查询按本绑定隔离，ACK 丢失只查原事务，未知不会盲重写。
- 同步使用读取过一次的完整缓存和冻结修订，不在写前/写后再取整份配置。设备以 CRC/逐字节读回验证 NVS 再返回提交回执，Bridge 按冻结变更投影更新缓存和基线，保留未选项和较新的本地编辑。旧部分字段 BLE 作业暂停为 whole_network_required，需重新整行选择；不暗扩大范围。完整读取仍仅显式读任务。
- 首次会合先有界认证 HTTP；失败才 BLE wifi_match 最小诊断。正常成功路径无额外成功状态查询；用户显式“使用当前网络”或配置意图仍可核对版本。AUTH_FAIL 的报告绑定实际尝试 SSID/保存版本，不依赖断网后空 SSID；同配置认证/安全失败停止同样的自动重写/激活，其他原因有限退避。Bridge 无唯一当前环境映射先提示本地配置；缺项/不同先 BLE 保存再启用，已保存未活动只启用。设备已入网但 HTTP 不通单独 bridge_unreachable；401/身份错独立，实际认证 HTTP 恢复清旧错误。

## 2026-10-04 协议审核修订：失败报告与首次交汇按需诊断（尚未实施）

用户收敛：设备Wi-Fi密码不对/认证失败等明确连接错误应经BLE报告；正常连接不新增成功上报。Bridge首次交汇先尝试认证HTTP，无法访问时才在同次BLE会合同步最小连接诊断；当前网络相同仍不可达必须在Bridge页展示。此处为审核方案，未修改/部署代码。

1. 设备仅在连接失败原因发生/变化时提供有限错误报告，绑定设备MAC、目标网络ID/SSID、配置版本、本次唤醒/连接尝试；不携带密码或整套配置。认证失败提示核对密码/安全模式，单纯超时不断言密码错误。普通失败路径不能依赖WiFi.SSID()非空，否则认证失败清空SSID会吞掉原因。
2. Bridge建立/恢复通信的首次交汇，先进行一次有界认证HTTP尝试，沿用设备发现IP/身份校验；正常成功以实际HTTP通信为证据，不增加成功BLE报告或整份配置读取。HTTP失败后，本次BLE链路查询一次最小诊断：实际/尝试连接的SSID、是否关联/取得IP、已获IP、有限失败原因及关联版本；连接正常时这仅是按需回复。
3. 无设备配置→查询Bridge当前主机SSID对应的完整保存方案，缺方案/密码时提示配置；与当前映射不同→展示实际/目标网络并走BLE配置任务。比较按host_ssid→设备2.4GHz SSID映射，不能强求主机5GHz与设备SSID字符串相同。主机SSID权限未知则说明无法比较，不猜测网络相同。
4. 同目标网络且设备未连接→页面显示设备报告原因；同目标网络且设备已入网但认证HTTP仍不可达→显示设备已连接该网络、Bridge无法访问设备（携诊断IP/观察时间），不能据此判密码错误。HTTP401/403或MAC不符分别显示认证/身份问题，不归为网络不可达。候选IP仅在身份认证通过后更新登记，不盲信BLE地址。
5. 后续正常通信不轮询成功状态。新故障/用户重试/通信恢复再更新诊断；实际认证HTTP恢复可清除旧不可达提示。迟到的旧任务/MAC/网络版本结果不能覆盖当前状态；有界诊断不延期PowerPlan或关闭BLE前的交接期限。

## 两份方案和一份同步基线

- **Bridge 方案**：本机持久保存的目标配置，可离线新增、编辑、复制和删除网络项；保存只写 Bridge，不联系设备。
- **设备方案**：用户点击“读取设备方案”得到的完整无密码快照，包含全部绑定方案与旧 USB/AP 配置。每次读取标明设备 MAC、配置修订、完整性和读回时间；当前连接只是附加运行状态。
- **同步基线**：上次成功同步并确认的字段值/设备修订，用于区分 Bridge 修改、设备修改和双方冲突。不把当前表单或旧快照当作设备现状。

进入页面默认展示 Bridge 已保存方案与已有设备快照，**不自动扫描、不强制读设备、不要求设备在线**。没有设备快照时仍可编辑 Bridge，但不能报告“相同”或计算设备缺项。用户可主动提交读取任务；设备不可达时保留任务和旧快照并明确标旧时间，等下一会合继续。

Bridge 是“希望设置成什么”的来源，设备是“实际已保存什么”的来源；双方都持久保存各自内容。读取不导入、不覆盖；本地保存不推送；同步是独立的显式动作。默认同步配置不切换当前网络，启用仍是独立动作。

## 信息结构与页面

沿用完整表格布局，Wi-Fi 页包含三个区：

1. **Bridge 方案**：展示本机完整方案集合和网络映射，可离线编辑；“新增网络”“保存到 Bridge”。字段为方案显示名、稳定网络 ID、主机匹配 SSID、设备 SSID、密码处理方式；编辑区显示本地未保存变更。
2. **设备方案**：按钮“读取设备方案”，展示实际完整集合、绑定归属、legacy、设备容量、启用版本和当前连接。其他 bond 与 legacy 初版只读；不因为只有本机可写就只显示本机一项。
3. **比较与同步**：按稳定身份对齐双方网络项，列“Bridge 值 / 设备值 / 差异 / 本次处理”。每个网络只提供整条方案选择；勾选需要覆盖的网络，选择方向，再预览完整变更清单。

首选并排比较表；小屏把一行的双方值上下排列，不隐藏另一侧。页头始终可见设备名/MAC、Bridge 最后保存时间、设备最后读取时间与快照完整性。读取后保留当前编辑区，不跳页、不抹草稿；当前任务简要显示，执行记录默认折叠。

| 差异状态 | 判定与默认处理 |
|---|---|
| 字段一致 | 双方可比较元数据一致；不重复写设备；密码仍单独标“未比较” |
| 仅 Bridge 有 | 可选择新增到设备；不自动推送；新增凭据不足时提示补全 |
| 仅设备有 | 可选择导入 Bridge；不因本地缺项自动删除设备 |
| Bridge 修改 | 有基线且只有 Bridge 偏离；推荐同步到设备 |
| 设备修改 | 有基线且只有设备偏离；推荐导入 Bridge |
| 双方冲突 | 同一字段两侧均偏离基线且不同；选择整条方案和覆盖方向，默认不勾选 |
| 首次发现不同 | 没有基线，不能猜谁更新；显示双方值并要求选择方向 |
| 明确删除 | 必须存在用户显式删除意图；预览列出删除项，活动项/无权限项阻止提交 |
| 未知/过期/部分快照 | 不把缺项认定为新增/删除；先读完整版本或标记等待读取 |

同步范围是本次勾选的整条网络配置；“全选差异”只选可操作项，不能夹带只读、冲突或删除项。没有默认“用整份覆盖另一份”的按钮。若未来支持整份替换，也必须有独立预览和明确删除授权。

## 双向同步流程

### Bridge → 设备

1. 离线编辑并保存 Bridge 目标方案。
2. 主动读取设备方案，或明确使用已有快照预览；快照过旧/不完整时，发送前先重新读取修订确认。休眠设备显示“等待会合/需 BOOT”，不假装已同步。
3. 在比较页勾选新增/更新等差异，选择“Bridge → 设备”，生成新增、更新、删除、凭据操作的变更清单。活动方案修改显示“同步后产生待启用版本，当前连接不变”。
4. 用户点击“同步选中项”提交异步作业，实际会合时按 MAC/bond/权限/expected_revision 发送原子变更集；普通配置编辑走物理维护授权，启用/自动选网继续遵循业务 owner。
5. 成功持久化后回读目标修订与选中整条配置，才显示“已同步”；Bridge 目标保留，设备快照和同步基线更新。仅收到 ACK 显示“设备已接收，待确认”，不能报双方一致。

### 设备 → Bridge

1. 主动读取设备完整方案，在比较页选择要导入的整条网络配置。
2. 选择“设备 → Bridge”，预览本地新增/更新和与未保存草稿的冲突。
3. “同步选中项”只更新 Bridge 本地方案，不写设备、不启用网络。导入保留源绑定/legacy 属性，不伪造可写身份。
4. 导入后记录可比较字段的基线。本机绑定密码随首次完整读取缓存，导入/复制保留已缓存密码；其他绑定/旧快照未知密码不能伪造，缺失时提示补全。

两个方向均支持按项同步；同一个变更清单只采用一个方向，避免一次操作含义混杂。冲突可逐字段选择保留 Bridge/设备值，形成新的 Bridge 目标后再同步。被删除项的缺失只有在完整快照和成功确认后才成立。

## 异步会合作业：读取与同步不以首次连接成败结案

最新用户要求：读取和同步设备方案都通过异步会合执行。点击按钮返回已接受的 job_id，页面立即显示排队状态；设备离线、深睡、扫描暂未发现或一次连接超时只是等待/可重试原因，不能把整个任务直接判失败。复用现有设备延后作业/会合调度器，增加 Wi-Fi 读/同步作业类型，不另起永久轮询服务。

| 作业状态 | 含义与后续动作 |
|---|---|
| 已排队 / 等待设备会合 | 作业意图已保存；等待 device_first、UDP/已验证 HTTP 恢复或用户 BOOT |
| 等待维护授权 / 等待凭据 | 具备联系机会但缺物理编辑权限或密码输入；任务保留，明确提示补充 |
| 正在连接 / 读取 / 同步 | 本次有界尝试，记录阶段、次数和最近错误；不阻塞 UI |
| 暂时失败 / 等下次会合 | 当前传输不可用；保留已确认进度，按退避等待下一次真实会合 |
| 设备已接收 / 待确认 | 尚未获得持久化/回读证明；再会合先查询原 request_id/修订，不能盲目重写 |
| 需要处理冲突 | 重读发现批准的字段已变化；保留双方值和原变更，暂停写入 |
| 完成 | 读到完整快照，或同步后的持久修订和所选字段已确认 |
| 已取消 / 已过期 / 不支持或请求无效 | 明确终态；取消已提交项不伪装回滚，结果说明实际确认范围 |

调度规则：

1. 按精确 MAC 串行调度，同一读取范围的重复点击复用在途读取；同一冻结差异的重复提交返回原作业，不重复配置。不同设备独立，Wi-Fi 作业与普通数据/OTA/模板作业共享已有传输互斥。
2. 已授权读任务等待正常设备会合，可经认证 HTTP 的正式窗口完成全量读取。只有 BLE 的短机会先完成必要身份/业务 ACK，并记录可用能力；不为了全量读取/写配置无限占用短 BLE。需要物理授权的编辑等待 BOOT，显示等待授权，而非普通连接失败。
3. 单次连接/分页/写入有硬超时；暂时错误退避可采用 5/15/60s，上限 60s。它们是下次尝试的最早时间，**不是每隔这些秒强行扫描/唤醒**；优先由实际会合事件驱动。等待不改变设备 radio 截止、owner 或 PowerPlan，不请求系统禁止睡眠。
4. 作业默认有效期可设 24h，期限只控制本地意图，并不让设备醒 24h。UI 显示到期/最近尝试/下次会合条件；到期或用户取消终止后续调度，期限内暂时失败保留任务。MAC 不符拒绝该候选并继续等目标；协议不支持/无效请求是明确错误，不无界重试。
5. 同步提交时冻结本地目标修订、勾选范围、方向、原设备基线和 request_id。实际会合后先读当前修订：无关字段变化且已批准目标字段仍匹配基线，可更新 expected_revision 后执行原差异；目标字段已变则需要处理冲突，不自动扩大/改写批准范围。
6. 发送后断链先进入待确认；下一次会合查询原提交结果并读回配置。确认已提交则完成，确认未提交且原条件仍成立才重试；无法判定时继续待确认，不将“连接断开”显示为“配置未保存”。分页快照失效可从新快照起点重读，但旧完整列表一直保留。
7. 关闭面板/切换设备不取消作业；取消是明确按钮。同一设备新的同步意图不覆盖已发送作业；尚未发送的旧意图可由用户显式替换。同步后只将发送的本地修订记入基线，新编辑仍显示待同步。
8. 作业元数据、非秘密变更和回读基线持久保存，Bridge 重启可恢复等待/待确认。密码不进入队列 JSON；仅有内存凭据的任务在重启后转等待凭据，允许重新输入继续原意图，不静默丢任务。系统安全凭据引用仅在用户已选择记住密码时使用。

设备→Bridge 可明确区分“导入已读取快照”（本地立即完成）和“重新读取后导入”（创建读/导入作业，等待会合后校验本地目标修订再导入）。读取成功不会自动把设备值覆盖到本地；同步方向和选中范围始终保留。

界面增加作业状态条：任务类型/目标 MAC、等待或执行阶段、最近尝试及原因、次数、过期时间、取消与重新尝试。异步结果按 job_id/MAC/页面 generation 核对，失败不清表、不跳页。示意可演示“连接失败→保留任务→下一次会合继续→回读确认完成”；它不代表真实设备作业已实现。

## 保存、试连与启用

| 操作 | 修改范围 | 网络与显示行为 |
|---|---|---|
| 保存到 Bridge | 本地目标方案 | 设备无变化，离线可用，不推送、不试连 |
| 同步到设备 | 设备保存的方案/待启用版本 | 不切当前 Wi-Fi、不重启、不改变显示 Bundle/active context |
| 临时试连 | 选中的已存网络或当前候选 RAM | 有界试连，报告关联/DHCP/HTTP；成功、失败、取消都恢复原连接，不自动同步或启用 |
| 启用 | 明确选择的设备已保存版本 | owner 校验，获得 IP 后才提交活动引用；失败恢复旧连接与旧活动版本 |

编辑当前活动网络时，旧活动版本一直保留到显式启用新版本成功，避免“同步不切网”却在下一次唤醒偷偷应用新密码/SSID。活动项删除要求先选有效替代，不能在批量同步中默默删除。试连进度留在当前页，设备屏幕保留既有内容；断链/重连不能当作完成，检测到复位应报“设备重启，结果未确认”。

## 数据一致性和存储

- Bridge 目标、设备快照与基线分开存储，按设备 MAC + 本机 bond 归属隔离；不混入显示 Profile，不改变设备数据投递许可。新增本地网络使用稳定 ID，不以 SSID/显示名为主键。
- 比较用可编辑元数据；设备当前连接/IP/验证时间作为运行状态，不随双向配置同步覆盖。其他绑定/legacy 可显示/导入为只读参考，普通同步不得改其凭据或归属。
- 全量快照分页冻结，包含 revision/snapshot_id/complete。读到一半或跨版本失败保留旧完整集合，不清空页面、不中途计算缺项。
- 同步变更集带 expected_revision 和 request_id；容量/权限/字段/凭据先整批校验，再一次原子提交。不半改配置、静默裁剪或隐式删除。若当前固件没有原子批量能力，能力协商明确限制为单项并报告逐项结果，不能标整批成功。
- 发送前只读检查设备修订，变化则重算差异/报 conflict；拒绝过时覆盖。失去 ACK 后查询 request_id，再回读确认，不重发凭据猜结果。
- 若发送期间 Bridge 本地目标再次修改，仅确认“发送的那一版”；保留新草稿并显示仍有差异，不能将最新本地值误标已同步。
- 取消已提交写入不能假回滚；报告实际提交修订。设备离线允许保存目标和同步意图，但等待状态必须与已应用分开，发送前重验快照/凭据/owner。

密码不参与普通相等比较，也不从设备回读。Bridge 方案记录凭据意图 `保留设备密码 / 更换密码 / 开放网络`，普通 JSON 与日志不存明文密码；新增/更换密码在实际加密同步时提供，临时输入结束清理。若用户希望离线保存完整新凭据，另使用系统钥匙串/Windows 凭据存储，仅保存引用；本轮不默认新增密码持久化或系统权限。导入设备方案不凭空生成 Bridge 的密码。

## 自动选网与同步的区别

自动选网依据**Bridge已保存targets与当前真实主机SSID**，通过BLE单条查询核对设备版本；配置一致只传网络ID/版本启用，配置缺失/修改则复用物理维护写入和回执确认。未保存草稿不参与自动选择。主机 SSID未知/无映射/有线/权限不足均不猜测；同目标不反复断网，deep 等正常会合，旧事件合并后再检查当前 SSID/owner。短 BLE 会合不读取整套方案、不开展人工长试连；只有正式 light/物理维护机会才执行网络操作。
