## 2 分阶段任务要点

### P0 固定合同与数据边界

- 按现行HTTP/BLE入口列出允许的op/字段/大小及成功证据。软件不匹配返回明确错误；不引入版本协商矩阵。
- 列出所有生产入口：自动会合、HTTP周期、presence/report、UI/MCP、Wi-Fi管理、首次绑定、Bridge OTA客户端、独立OTA。确保没有旁路。
- 只读记录当前持久格式、principal/namespace和未确认记录，不输出token/密码。准备私有备份与一次性转换方案；把TransactionKey、内容指纹、未知状态及高水位转换为最终软件可执行的围栏，不能只保存新软件不识别的旧blob。没有证据不得清空历史未知回执。
- 旧测试active_protected拆成“唯一配置拒删”和“另有配置可删、live active不变”，先依据合同修fixture；不能把旧失败算本次新回归。

### P1 原事务结果与持久确认

- 把原写响应、结果查询响应、传输失败分成类型；使用同一业务状态转移处理HTTP/BLE反馈。
- 统一TransactionKey；存储校验、查找、ACK和高水位维度全部一致。
- 作业取消/过期与确认义务分离，确认调度有界且借自然机会，不延长RF窗口。
- trial新终态/activate分阶段结果按设计§4.4提供充分持久证据；旧未知记录不得猜测退役。结果容量满仍允许查询/安全只读。
- 将HTTP真实写入进度传到统一结果；校验socket/worker取消后的在途行为，不能仅用外层timeout装饰。

### P2 建链至收尾的一个生命周期

- 先写复现connect失败后disconnect pending的测试，确认它经过与生产相同的connect/setup控制流；不能走现有Fake提前构造link分支。
- scan/connect/discover/INFO/身份拒绝/成功/取消均走一个收尾出口；保留平台有依据的停扫描、重发现行为。
- 为本次尝试分配绝对截止并预留清理；控制线/真实设备操作仍按项目细则，不在单元测试里访问设备。
- 原生请求迟到、外设移出map、native worker失效测试：旧代际不污染新会合；不能恢复时有限报错并停BLE，不不断spawn worker。

### P3 收敛所有调用者并删除

- 上层只传业务操作；每设备有界调度，BLE全局许可只包射频资源；HTTP尾部与回报接收独立。
- 固件必需认证context，业务处理器只一份。当前首次绑定/凭据恢复仍可用，不能用删除legacy的名义删除当前离线配网。
- 按设计§9逐项删除旧成功路径、旧缓存、旧恢复驱动及多余测试夹具；建立剩余命中清单，逐项解释保留原因。
- 内部没有“新栈失败转旧栈”、环境变量回退、版本宽容或旧报文翻译。通用明确拒绝旧输入可以保留，不算旧协议支持。
- 如旧持久格式需要转换，发布前选定并验证一次性转换方式，不假定工具已存在；转换后的未知记录及围栏须被最终软件识别。未能完成安全转换则阻止该设备新写及发布放行；最终运行服务不承载旧网络协议/迁移命令。

### P4 保持OTA独立且简单

- 不把原生OTA接入execute业务接口，不加frame/session/owner/job/Plan前置，不改原生双槽。
- `/doUpdate`每请求鉴权，上传状态与认证状态分开；无文件、错误target、并发busy和写失败不能假报成功/统一401。
- 完成/失败/取消/20秒停滞均回收维护锁和Update状态；第二次正常上传可进入。维护锁不续正式计划。
- Bridge可选作业保留冻结镜像、预检和重启核验；`/api/ota/image`仍为可选只读证明，不改变手动上传流程。

### P5 可观测性与本地证据

- UI/MCP使用相同LastObservation、LastAttempt、SchedulerHealth、PowerExpectation；失败不抹历史值，历史值不冒充当前可达。
- 诊断按阈值/关键失败/睡前本地提交，与HTTP上传解耦；重复事件合并，明确丢失/gap。
- 改显式持久格式前先确认空/单条/典型/上限资源预算；写新格式并读回成功后才能退役旧格式，原子性保留。
- 两小时目标必须写清保证的摘要、事件率及突发上限；不以旧样本平均速率宣称全事件无损。

### P6 一次性切换现行协议

- 最终软件不支持旧协议，更新次序不依靠双栈。先暂停业务发送并持久保存确认义务，保留独立OTA凭据和私有备份；使用独立OTA更新设备，再启动匹配Bridge，认证验证运行镜像/身份和状态。
- 中间版本不匹配期间明确暂停业务，不擦设备数据、不换未知事务ID。设备或Bridge更新失败时独立OTA仍可用，正常电源策略保持；需要物理唤醒属于原有机制。
- 恢复的是匹配的一对软件和可验证的数据状态，不假设回滚旧Bridge二进制可读新存储。原生OTA双槽不自动证明回滚已经可用。
- 更新PROGRESS与权威协议/实现对照；软件候选、实际部署和未验边界分别记录，未经要求不提交Git。

## 4 资源与实机门禁

- 不改变既定会合周期、浅睡期限和电源优先级；比较同场景下RF开启时间、无进展退出和正式deadline，确保没有隐性续期。
- 嵌入式变更给出空/单条/典型/上限持久字节、峰值RAM/栈、擦写次数和写入时延；错误记录按实际条目分配，不预留空仓库。
- 构建前读agent-operations对应节，默认 `pio run -e zectrix-note4-b`，核对版本/尺寸/SHA；匹配ELF运行Wi-Fi栈检查。只列验收要求，不表示本轮已执行。
- macOS UI涉及变更时运行 `node tools/test-device-page.mjs`、`bash tools/test-wifi-ui.sh`并审阅窄宽截图；合成IPC不代替Rust/设备通信。
- CoreBluetooth真实回调、ESP32网络、Flash掉电、独立OTA和电源实机验收不能由Fake替代。设备访问/部署按当时授权和身份核验执行，本计划不是本轮烧录操作。
