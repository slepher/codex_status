# Bridge multi-instance launch — 2026-09-24

The main checkout owns this change. `tools/start-bridge.ps1` now accepts `-Instance`, `-Port`, `-McpPort`, `-IconShape square|circle|diamond`, and optional exact `-DeviceMac`/`-DeviceIp`. Named instances require both ports. The script checks the requested listeners, tracks a PID per instance, and confirms the launched executable owns its HTTP port. The default call keeps 8765/8766 and its existing PID/log names.

Windows process locks are keyed by instance name. A named instance uses `<exe>/instances/<name>/data`, a distinct Bridge owner ID (`<original 4-hex host ID>-<instance>`, at most the device's 32-character claim limit), and a shaped tray background; the default retains `<exe>/data` and its owner ID. Named instances do not bind the firmware's fixed UDP announce port 8767; they use MAC-specific HTTP/BLE discovery. Their autostart menu item is disabled so they cannot change the default registry entry. The watchdog inherits instance environment on restart. No ROM or protocol change is required.

Validation: `cargo check --offline -p bridge-app` passed; `cargo test --offline -p bridge-app --bin bridge-app` passed 23 tests, including claim-ID length and shape checks. An isolated `cargo build --offline -p bridge-app` passed. Two probe instances using fake MACs and loopback IPs ran simultaneously: `probe` HTTP/MCP 8875/8876 (PID 46548), `probe2` 8877/8878 (PID 9160), while the existing default occupied 8765/8766 (PID 27552). Repeating the probe launcher returned its PID without starting another process; direct launch with the same instance name was rejected by the process lock. Separate probe data roots were created. Both probe watchdogs and apps were stopped afterward; the existing default instance stayed running. `git diff --check` passed.
