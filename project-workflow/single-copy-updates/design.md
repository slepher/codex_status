# 单份内容、暂存下载与动态容量
2026-10-11，C9 实施设计。用户明确取消所有设备的项目自管内容/应用 A/B，保留原生固件 OTA 双槽；实施中进一步允许完整临时下载包。

## 生命周期
1. 认证、owner/session/MAC 与长度检查；按当前剩余空间准入。创建 incoming.bin，旧内容和 data_contract 继续有效。下载失败或断电不退役旧内容。
2. 下载完成，流式校验长度/CRC/owner/job/目标和模板结构。此阶段失败仍保留旧内容。
3. 即将替换时停止内容绘制/切换，进入固件内置维护画面，清空旧 context/contract/data，释放旧字体。退役提交标记，删除旧文件，将 incoming.bin 移动为 content.bin；不复制整包。
4. 逐字体解码校验，逐模板解析/编译，向同一文件追加缓存，读回校验后发布小型提交记录。后续模板/字体/存储错误可使内容丢失，回到内置等待发布画面；不恢复旧包。
5. 已提交 job 的 owner/request/length/CRC/原提交 context 保留为短回执，设备重启后仍可查询/重放原事务。身份、网络、配对和原生 OTA 均独立。

下载不延长 PowerPlan。应用文件也采用下载后停应用、再覆盖的顺序；稳定更新服务/内置画面不随应用被覆盖。应用退出必须排空线程、回调和文件引用，无法退出则拒绝。当前 ESP32 只实现 Bundle，AP01 独立应用加载/退出/恢复仍待硬件验证。

## 持久格式及迁移
新 content.bin 是精确冻结正文 P（原JSON或下述CSZ1容器），后接 N 个缓存记录。每项为 17 字节有界 ID、显式 little-endian u32 长度、既有 CTP1 缓存（12+11321 字节）。长度为 P+11354N，1–8 项。

state.bin：12 字节显式编码头（BCS2、正文长度、正文 CRC32）加不超过2048字节的版本2 JSON。记录文件长度/CRC、正文偏移/长度/CRC、缓存偏移、实际 IDs/initial、目标、job/context/seq 和事务回执。未知版本、越界、损坏不加载。state.tmp 仅用于原子替换这个小记录，绝不是内容 A/B。

旧 CAB1/SBM1 只作一次读取迁移：选最新校验有效记录，验证它引用的文件，移动到 content.bin，写新小记录，再删旧 a/b/m0/m1/rx。content.bin 一旦存在，启动不会回到旧槽；迁移中断允许进入内置恢复。不格式化文件系统、不擦网络与认证。原生 OTA 分区表未改。

## 动态准入和资源
协议 bundle_storage_protocol=2，HTTP 认证状态及能力报告实时 max_bundle_bytes。Bridge 更新能力缓存并去掉全局256/512 KiB产品截断；旧固件缺能力标记仍保留256 KiB兼容上限。整数运算另以 u32::MAX/2 作为线格式边界。

本实现保守下载上限为实际 free + 可退役 incoming 的逻辑长度 - 49152字节预留 - 90832字节八项缓存。BEGIN 删除旧 incoming 后再次检查实际 free；不将当前内容或原厂文件算作可在下载前回收的空间。该预留优先保证无需猜测物理块回收量；具体安装时再按实际模板数检查。零容量是明确拒绝，不回退默认值。

不整包建 DOM：元数据 JSON 分配预算8 KiB、每个模板解析128 KiB、单源32 KiB、每个字体解析80 KiB、单字体48 KiB/最多8个。正文中未使用的大资源/编译十六进制直接跳过；运行只有活动 CtTemplate，安装另用静态11321字节编译暂存。资产集只加载一次，替换时释放旧集合。字体解码、序列化缓存、源编译器、网络和显示分配仍需计入真实堆峰值；这些解析预算不是整机内存峰值承诺。字体解析峰值约 F+80 KiB，模板源序列化峰值上界约 F+128+32 KiB，另计静态模板、编译器/底层库和网络。实际分配失败返回错误，不缩减模板数量。帧/栈以候选 ELF 和实机验收为准。

## AP01 压缩暂存评估
/resource 名义1310720字节，实际原厂占用 O 未知，4 MiB PSRAM 配置不是空闲堆证明。AP01规划容器仍按 S=64+P+11365N 估算（不是 ESP32 新格式的精确字节），共同预留R=65536，应用A=262144。同大小新旧包更新时：

| Bundle正文 | 稳态A+S+R | 原包暂存峰值 | 余量（原厂占用前） |
|---|---:|---:|---:|
| 256 KiB，8项 | 680808 | 942952 | 367768 |
| 512 KiB，8项 | 942952 | 1467240 | 超156520 |

压缩暂存C时必须同时满足旧驻留+C及新驻留+C的峰值；若解压后立即按块删除输入仍需另证明回收算法，不在当前承诺范围。512 KiB正文若压到256 KiB，峰值1205096，余105624（约103.1 KiB），还须扣O及额外开销。不能以假定50%压缩率保证足够；压缩不能解决最终内容自身放不下。

0031原厂SHA256 8a721fc8ef25458d415b2460e4a251e0503a82f7743fdff85b12612190e5c1cb。存在 LodePNG DEFLATE/zlib 诊断，完整长度表0x521c68、距离表0x521b78及码长顺序表0x521b18；主代码0xa0105776/0xa010578e实际构造前两表地址。证据见 ../../artifacts/c9-ap01-compression-evidence.json。这是解码代码存在的强证据，不是入口/ABI已验证。

优先研究复用原厂解压；Bridge压缩，设备只解压。LodePNG公开接口以缓冲区工作，不默认视作流式文件解压；独立小块zlib可降低峰值，必须验证输出硬上限/摘要、内存分配与失败路径。AP01压缩适配与可调用入口尚未实现；Note4实现见下，不将其测试当作AP01实机证据。上游接口：https://raw.githubusercontent.com/lvandeve/lodepng/master/lodepng.h 。

## Note4 统一压缩实现（2026-10-11 续）
先实现 Note4，AP01 仅遵守格式约定，入口/实机后续调查。本轮不部署。复用芯片 ROM miniz；宿主复用已依赖的 miniz_oxide。压缩容器同时作为下载及驻留正文，追加原有编译缓存；有界读取器按块解压，避免完整解压暂存和修改单份替换流程。每次读取只持有一块输入/输出，压缩器仅在 Bridge。

统一 `zlib-blocks-v1`：24字节头为 ASCII `CSZ1`、LE32 原文长度、原文CRC32、块大小16384、块数、保留零；随后块数个LE32压缩长度，接各块独立zlib流（最后一块原文可短于16384）。无字典，每块压缩长度1..16512，必须消费全部输入且输出精确等于该块声明原文长度；整个原文CRC32再次校验。不接受尾部字节、未知标识/块大小/保留位、截断、溢出、输出超限。总原文处理上限由设备 `max_bundle_decoded_bytes` 报告（本实现取内容分区总容量），物理下载上限仍由实时空闲量决定，不用固定256/512KiB门槛。

能力 `bundle_compression=1` 表示此格式，缺失为0；未知值拒绝。发布时将获益的压缩包以base64冻结在任务 `frozen_wire`，重试/重启原样发送，不因能力刷新而重新编码；旧任务/旧设备发送原JSON。BEGIN/CHUNK/COMMIT的长度、CRC、offset和回执都针对冻结的传输字节，原JSON canonical/hash不变。鉴权和owner/目标/完整校验在覆盖之前完成。存储BCS2的payload字段继续描述物理正文，可同时读取旧JSON或CSZ1；未压缩编译缓存偏移不变。

预算：单实例16384B输出+16512B输入+10992B miniz状态+4×(实际块数+1)B偏移表，均按需堆分配；旧JSON不分配解压区。未配置0B；单块43896B；128KiB原文8块43924B；4MiB原文256块44916B。另计分配器元数据，解析/编译/字体/文件系统/网络开销，不是整机峰值承诺。安装预检读取器在加载字体前释放，避免双解压区叠加；原文不整包进入设备RAM。匹配ELF：BundlePayload方法32–64B直接帧，bsInstall992B、loadFonts480B；ROM解压调用链/运行高水位仍需实机。候选BIN比.79增加3616B，静态RAM119148B不变。生产编码器的Note4字体Bundle样本10608→3134B（减70.5%），编译缓存另计，不推广为任意包固定比例。

已验证跨块/重启字体、头部/长度/校验/尾部损坏与输出上限、真实HTTP八模板压缩上传、丢ACK后跨重启重放、Bridge能力变化后冻结字节不变及原格式兼容。最终候选独立打包，未触及诊断现场。
