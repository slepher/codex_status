## HTTP边界

| 服务 | 默认端口 | 职责 |
|---|---:|---|
| 稳定维护/应用管理 | 18080 | 四位码配对/绑定凭据、维护健康；原生固件OTA、可执行App安装与诊断属于此层 |
| Codex Status/显示业务 | 18081 | 认证状态、claim、数据快照、显示模板Bundle begin/chunk/commit、activate；不接PowerPlan |

模板Bundle是显示内容，不等于可执行App。两服务共享受控身份/绑定和owner规则，但维护健康不依赖Codex context；不能仅换URL路径伪装服务独立。UDP分别公布http_port与maintenance_port，Bridge按来源IP构造两端点；端口相同或维护端口缺失即拒绝，不静默退回同一服务。配对经维护端口，确认后的业务状态经业务端口认证。

已落实在Bridge路由及隔离device-sim：两监听/两服务任务，业务监听退出不终止维护。停止业务监听后，维护/health及pairing/info保持可读；健康需绑定token，无token401，维护端口没有业务status/data路由。固件/可执行App安装在宿主模拟器中明确标unsupported，没有伪造OTA成功。该验收仅证明监听/任务生命周期，不证明原机进程内存隔离或原ROM接线完成。

## 0041分区证据

冻结原件6769704 B，SHA256 `972db4c136c7ed9e24a83c07c1a7fd62040ca018b08ca285216d26b1fee3c6b9`。
REA重新检查`0xa0059762`，资源设置窗口`0xa0059afa..0xa0059b4e`：在`0xeb0000`起建立`0x140000`（**1,310,720 B = 1.25 MiB**）分区，注册`/dev/resource`并以littlefs挂载`/resource`。独立`/data`仅64 KiB。Bundle应计入`/resource`自己的可用空间；先前只以/data不足判断存储不够并不充分。

在该明确条件下，空分区首次最大传输为 **1,162,544 B**。8模板未压缩更新需 **827,039 B（约808 KiB）**，距分区总量仍余 **483,681 B（约472 KiB）**，可供其他占用增量；若原机其他占用超过余量则需重新核算。CSZ1可进一步降低占用，但原生0041解压入口仍未完成，**不依赖压缩才宣布本例足够**。空盘最大传输不等于任意时刻可用额度，更新时须扣除当前内容。

64 KiB /data连本实现的49,152 B保留与90,832 B缓存准入预算都容不下，应避免将Bundle放在那里。满盘注入在开始接收前明确拒绝，并逐字节核对旧内容未改。8种组合均通过（1/2/4/8 × raw/CSZ1）。测试入口为`AP01_STORAGE_OUT=<已预建私有目录> cargo test -p bridge-core --test ap01_storage -- --ignored --nocapture --test-threads=1`，运行须遵守AGENTS目录提权要求。详细测量见`bundle-storage.json`及`measurement-tests.log`。

## GIF与是否移除整页

直接解析0041原件`0xa055fe44`的5项萌宠表，验证每项原生descriptor、320×240尺寸、完整GIF子块与结束符：五份动画合计 **2,153,808 B（约2.05 MiB）**，属于固件镜像内的XIP资源；整个ROM还存在屏保和充电引导等GIF，不能都当萌宠页删除。

**结论：当前样例在/resource预算内，不触发移除GIF整页。** 删除萌宠模块可以释放固件代码/资源空间，但不会自动增加/resource的容量或空闲量。若后续原机statfs或实际App/Bundle预算证明不足，应先明确需要的是ROM空间还是文件系统空间，再执行用户授权的整页移除；包括页面注册、正反导航、五项选择表、描述符、动画计时/回调与资源引用，不能只换一张空GIF。涉及持久空间布局时必须另核对native OTA/双ROM槽边界，本轮没有改分区，也没有占用备用固件槽存Bundle。
