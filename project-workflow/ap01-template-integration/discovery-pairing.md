# AP01 常在线与自动发现补充设计

2026-10-18。待实施、未部署；backlog C9。本文件只补充发现和常在线行为。配对权威为旁仓[双屏核对与旋钮确认方案](../../../cuktech-ap01-firmware/reverse/reports/ap01/screen-binding-design-20261014.md)。上一稿误加的六位输入码、物理开启配对窗口和PAKE全部撤回，不作为实施要求。既有EPD发现/配对/PowerPlan行为不变。

## 既定配对流程

沿用 `binding_method=screen_confirm_v1`：米家先完成Wi-Fi配网；Bridge点击绑定，双方显示Bridge固定四位数字与身份提示，用户在AP01按旋钮确认。最多一个待确认请求、120秒截止；原设计中的owner/维护闸门、候选token、原事务查询与持久提交规则不变。不增加输入数字步骤，不要求预先在设备设置打开窗口。

数字是人眼核对提示而非密码，首次采用原定局域网HTTP/token方案，不承诺密码学身份认证或防同网段窃听。完整MAC、boot_id、pairing_revision由GET /api/pairing/info读回；确认绑定后使用该关系凭据认证/api/status。广播本身不构成认证。绑定成功后通过显式 claim 请求取得占用，不自动发布 Bundle；2026-10-23 修订：新登记设备默认开启数据同步，已有设备保留保存的同步设置，数据需求仍以设备认证契约为准。

## 产品目标与入口

正常同一局域网内无需知道MAC或输入IP。设备页“添加设备”自动列出在线AP01，用户只需选择设备、点击绑定、在设备上核对并按旋钮。已有绑定在电脑/设备重启、DHCP换IP、换网返回后自动重连，不再弹配对画面。

原米家配网保留；Wi-Fi在线并不要求两端SSID相同（如同一LAN的2.4/5GHz）。条件是路由允许双向局域网通信。手动IP仅为高级诊断入口，不出现在默认添加流程。

## 主路径：主动探测＋设备通告

仅被动等设备五分钟一次通告，无法解决“设备早已开机，后来才启动Bridge”的首次发现。因此新增主动探测，同时保留通告。

| 时机 | Bridge | AP01 |
|---|---|---|
| 打开添加设备/点击刷新 | 对全部有效局域网IPv4接口主动探测，流式展示候选 | UDP单播回复探测的来源IP/端口 |
| Bridge启动/网络恢复 | 已绑定设备先尝试缓存地址，失败自动探测；网络代次变化直接探测 | 正常运行仍响应主动探测 |
| AP01首次获取地址/重连/地址改变 | 接收通告后按MAC合并候选、核验新地址 | 地址可用后立即发有界UDP通告 |
| DHCP静默换IP/通告丢失 | 原连接失败自动探测，不要求编辑设备 | 持续监听探测；后台沿用约5分钟通告兜底 |
| 进入设备Codex设置/重试连接 | 可即时收到新通告 | 可主动重发一次通告；不触发绑定 |

设备UDP发现端口复用8767。Bridge主动探测使用每轮临时UDP端口，AP01向请求来源端口单播回复；不依赖PC固定8767监听、也不依赖Bridge回连HTTP服务。现有默认实例8767被动监听继续复用；named实例也能用自己的临时端口主动发现，不能因被动监听禁用而无法添加AP01。按用户最新确认拆分两个服务：18080为稳定维护/应用管理与配对，18081为Codex Status/显示业务；分别监听、独立生命周期。实际端口由UDP分别公布，禁止以一个端口代替另一个或静默回退。

主动请求保留magic=codex-status，并增加discovery_v=1、kind=discover、128bit随机nonce和可选完整target_mac。AP01回复kind=discovery_reply、原nonce、model、完整mac、http_port（业务）、maintenance_port（维护）、binding_method、boot_id及短显示名。设备通告kind=announce，无nonce，只作提示。已有EPD无kind通告保留原分支，AP01新格式先按kind分派，不能落入旧逻辑误更新登记。

端点主机地址只取UDP来源，不信任报文中自报的任意IP/URL。HTTP端口校验1..65535，固定请求路径；不跟随到其他主机的重定向。探测只回来源，不接受第三方回包地址字段。

## 接口选择、期限与候选核验

- 枚举有效、有IPv4地址的本地LAN接口与真实掩码，包含Wi-Fi和以太网；默认排除loopback、无地址接口、隧道/VPN及无广播能力接口。按网络前缀去重，同网段多网卡保留可达路由。按各接口IP绑定套接字并向其定向广播地址发送，不把全部流量交给默认路由或假定/24。广播源必须落在对应本地直连前缀。
- 每接口在0/400/1200ms最多发3次同轮探测；一轮总预算8秒，UDP、HTTP候选核验和邻居补查共享该预算，单HTTP最多2秒、核验并发最多4。候选未全部核验则报告partial/预算用尽，不能假称网络里无设备。取消页面/网络变化后取消旧轮，旧轮结果不能覆盖新网络。
- 一轮候选按实际数量分配，最多32台；请求<=256B、回复<=768B，截断/未知版本/非法MAC/nonce错误直接丢弃。设备对同nonce去重，回复增加20–200ms抖动，单来源最多2次回复/秒；不广播凭据、账号、额度、完整绑定列表或网络密码。
- 初次发现：GET /api/pairing/info核对完整MAC、型号、binding_method、当前boot_id和pairing_revision，再显示“可绑定/占用中/维护中/名额满”。它仍是未认证的候选，只能由用户显式发起绑定；点击绑定前重新读取当前info，避免使用过期代次。普通扫描不弹设备配对画面。
- 已绑定发现：用原绑定凭据对候选端点认证/api/status，核对完整MAC及能力，成功后才替换持久endpoint、恢复后续owner流程；不迁移凭据、不新建身份。MAC相同但凭据失败为“需要重新确认/身份不匹配”，停止业务投递。缓存旧IP和候选新IP分开保存，UDP不能直接改可信地址。
- 临时候选30秒未见过期；已绑定设备保留在列表并显示离线，不因扫描无响应删除。以完整MAC合并不同接口和IP，同名/同四位码不合并。多个新IP声称相同MAC且未能确定唯一有效端点时标记冲突，不挑首个写入。

## 广播受限时的自动补查

主动探测无结果时，先读取Windows/macOS邻居表。已绑定设备按已知完整MAC找地址，再认证核对；首次添加可对最多32个本地直连邻居的18080端口读取最小pairing/info，并发/总时限沿用同一预算。邻居表记录同样只是hint。

现有ARP助手把网段写为/24，不能直接当新AP01通用流程调用。若需要主动ARP补查，只对已知MAC、已核对的真实小网段执行有界查询；较大网段仅使用邻居缓存，不盲扫整段或依赖厂商MAC前缀认定型号。macOS不为发现要求管理员权限。

UI区分：搜索中、发现并核验中、可绑定、已绑定离线、已被占用、局域网权限/防火墙受限、网络隔离或未响应、结果不完整。默认给“重新搜索/检查局域网权限/确认设备联网”操作。Broadcast被禁但单播可达时可能由缓存/邻居表找回；若设备从未被本机看到且广播/邻居路径均不可用，无法保证零输入发现，不能只提示用户输入IP就当流程成功。跨VLAN或访客隔离也不能靠输入IP自动解决；同LAN恢复后自动重搜。mDNS/.local及云账号不作为本方案依赖。

## 自动重连调度

同一网络共享一轮发现，多个设备/页面/MCP请求复用，避免逐设备广播风暴。正常认证通信成功时不重复搜索；端点失效、网络代次变化、Bridge启动或用户刷新触发。失败按2/5/15/30/60秒退避，加入抖动，上限60秒；网络恢复事件立即重试一轮，不等待旧退避。401或明确身份错误不无限重试凭据，不自动弹出新配对；409占用保留绑定、只读状态，不抢占。设备与Bridge地址变化不影响已安装Bundle或最后成功画面。

## 常在线与接口分工

AP01不接PowerPlan，不创建light电源窗口；Bridge按常在线能力跳过计划生成/下发，误调用返回结构化unsupported。屏保/熄屏不停止网络或发现，owner租约300秒、显式60秒续约沿用原设计，与电源状态分离。

发现新增UDP请求/响应及application service的“搜索设备”入口，UI和MCP共用进度、取消、候选及错误。配对API完全沿用原设计：GET /api/pairing/info、POST /api/pairing、GET/DELETE /api/pairing/{request_id}，不引入上一稿/api/pair/*或PAKE/session接口。绑定后的/api/status、/claim、完整Bundle、activate和data仍走各自既定认证入口。

## 实施与验收

1. ROM加入有界UDP响应/联网地址变更通告和原定pairing/info，复用已有网络线程边界；网络回调不直接绘制。
2. Bridge扩展现有8767通告分派，加入多接口主动搜索、临时候选、邻居补查和认证端点更新；取消旧AP01单路径/24假定。
3. 设备页把添加入口改为自动候选列表，绑定仍双屏四位码＋旋钮确认；MCP调用同服务。发现失败阶段可见，不改凭据/owner/同步许可。
4. 覆盖设备先开/Bridge先开、两端重启、DHCP换IP、2.4/5GHz同LAN、多网卡/有线/VPN、两个Bridge实例、多台同名设备、广播丢包与禁止、空邻居表、Windows防火墙/macOS局域网权限、重复/伪造回复、错误MAC/凭据、取消/网络切换迟到结果、占用与维护、屏保发现及无Plan运行。

目标验收：正常允许局域网互通的网络中首次添加与重连均零IP输入；故障网络准确归因并保留用户配置。文档完成不等于ROM/Bridge代码、实机发现或配对已完成。

维护层持有配对/凭据和自身健康入口，不依赖Codex数据context；模板Bundle是显示内容，begin/chunk/commit与activate随显示业务服务。应用可执行程序更新、原生ROM OTA和维护诊断属于维护层，不能交给Codex数据HTTP。宿主模拟器对未实现的固件/应用安装明确报unsupported，不伪造成功。业务HTTP停止后维护HTTP和pairing/info仍可读取；此项模拟验收不证明原机进程地址空间隔离。
