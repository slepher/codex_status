# AP01 维护核心构建与验证

2026-10-15。用户授权以旁仓库现有破解包为基础补独立维护界面/OTA，保留原厂OTA逻辑，只构建验证，不刷机、不额外逆向。沿用Ponytail最小复用原则；第三方仓库只读。

## 计划

先交付不依赖业务任务的维护核心：已有binding认证、设备MAC与完整principal核对、单事务流式接收、有界截止、包预检、停止业务、排他安装、结果未知后只查询原事务。核心给出内置维护文案，不调用业务绘制。宿主使用故障注入验证，RV32交叉编译并核对字节与栈成本。构建器固定现有0031-opt包身份，核对构建清单，明确报告设备适配是否完整。

现有破解源码只提供取包、文件读写、定时器、页面接口，未找到独立监听/任务启动、binding持久读写、安全停止业务、与原厂OTA共用的安装排他及App文件安装接口。缺少这些接口时不能把宿主验证或未挂接载荷称为可运行维护ROM；构建报告须标`rom_ready=false`，不得向原ROM附加无人调用的代码冒充完成。设备适配只使用现成已说明接口，禁止推测地址或调用ABI。

## 实现约定

维护核心由单一维护执行单元串行调用，原厂OTA不经本核心；排他回调必须覆盖原厂OTA，不能用本核心的busy代替。认证失败/错误MAC/不同principal不得改变事务。事务ID为16个不透明字节，principal为1–64字节显式长度完整比较；绑定凭据由适配器核对，不保存在事务或日志。接收总截止不随分块/重试延长；同事务重试返回原进度，偏移不符拒绝，不重复写。包按实时可用空间准入并写暂存，校验成功才停业务和安装；停业务失败不覆盖，未明确提交成功返回未知，不换ID重发。一次安装回调只执行一次，未知结果只查询原事务。

设备持久日志/掉电恢复、真实网络服务和设备绘制均须由已验证适配提供；本轮在接口缺失处明确停止接入，不伪造持久成功。维护文案生成不等于设备屏幕已验。

最终证据：`artifacts/ap01-research/maintenance-verified-20261015/maintenance-build.json`。宿主地址/未定义行为检查及同一套RV32测试实际执行通过；覆盖完整principal/错误MAC/错误凭据、同ID冲突/跨事务旧请求、错偏移/重复块/超量、截止不续期、原厂busy模拟、停业务失败/超时、未知安装不重复提交、确认后回执写失败、重启未知查询、恢复后显式重传、逐字节损坏/所有截断、带正确CRC的非法阶段/数量/类型及1–64字节principal记录。测试适配器为合成实现，不证明原厂并发排他、掉电原子性或真实安装。

交叉产物为静态库及核心ELF链接检查，不是完整ROM；链接地址仅供离线检查，不是AP01注入地址。代码与只读数据3330 B，静态data/bss为0；状态对象136 B、调用者请求100 B，分块缓冲借用调用者且上限1024 B，核心无动态分配。编译栈报告核算最大已知核心链256 B，设备回调/网络/UI栈及实际峰值未知。没有绑定表实现，不填写0/1/4/8条绑定的虚假成本。
