## 复现

以下在提权启动的WSL Ubuntu-24.04 shell执行。输出文件名必须不存在；目录已经提权预建。构建会创建子目录，须按AGENTS使用提权命令；不需要PIO、设备或原厂后台。

```bash
cd /mnt/d/Documents/PlatformIO/Projects/codex_status
bash tools/ap01/build-qemu-ap01.sh \
  /home/slepher/qemu-ap01-0041/source /home/slepher/qemu-ap01-0041/build

python3 -B tools/ap01/run-qemu-ap01.py \
  --qemu artifacts/ap01-research/qemu-0041-20261017/qemu-system-riscv32 \
  --image artifacts/ap01-research/ap01-1.0.2_0041.bin \
  --mhint-latch --mtvt-latch --cache-csr-latches --boot-mmio --efuse-shadow \
  --run-to-trap --timeout 20 \
  --cpu rv32,x-ap01-p=on,xtheadba=on,xtheadbb=on,xtheadbs=on,xtheadcmo=on,xtheadcondmov=on,xtheadmac=on,xtheadmemidx=on,xtheadmempair=on,xtheadsync=on \
  --output artifacts/ap01-research/qemu-0041-20261017/rom-next.json

python3 -B tools/ap01/probe-qemu-injection.py \
  --qemu artifacts/ap01-research/qemu-0041-20261017/qemu-system-riscv32 \
  --image artifacts/ap01-research/ap01-1.0.2_0041.bin \
  --output artifacts/ap01-research/qemu-0041-20261017/injection-next.json

python3 -B tools/ap01/test-qemu-ap01.py \
  --qemu artifacts/ap01-research/qemu-0041-20261017/qemu-system-riscv32 \
  --output artifacts/ap01-research/qemu-0041-20261017/tests-next.json
```

去掉所有功能模型参数和`--cpu`可复现generic RV32的MHINT非法指令。`--run-to-trap`只以PC=0断点捕获本阶段零mtvec异常，不是普适异常捕获器；后续mtvec安装后需增强捕获。超时报告PC仅为最后观察值。

## 模型边界与下一步

映射：480KiB片内RAM四别名、4MiB PSRAM三别名、16MiB只读XIP窗口；尾部未装载区为零是模型初态，不能据此认定真实Flash空闲。没有BootROM/Boot2快照、完整Flash/文件系统和设备OTP。

MHINT/MXSTATUS/MHCR/MEXSTATUS为可关闭的功能存储，初始0是假设；没有真实缓存、权限、复位/睡眠副作用，MHINT bit20仍未知。MTVT/CLIC寄存器只保存配置，不派发中断。CPU显式启用的QEMU XThead子集及通用rv32不是严格E907兼容性证明。

启动MMIO白名单来自现有模型及固定SDK `41bf338a57be53919d99f6c6715a96100428c97d`寄存器定义，不模拟完整外设。eFuse shadow只读回原厂代码已经写入的字节；未初始化读取、未知MMIO和OTP读/写触发明确失败。SDK对应`drivers/lhal/src/bflb_ef_ctrl.c:444`的清shadow→配置→触发→等待链；不能把锁存寄存器当OTP加载完成。

下一步先实现有依据的OTP只读事务，明确使用真实备份还是**显式合成fixture**；合成身份/校准不能宣称匹配设备。之后按实际轨迹补计时、中断、Flash/BootROM及显示/输入，逐项验收NuttX和应用。当前不能宣称整ROM启动、实机等价或刷写安全。完整MiIO/MiBLE源码恢复不是这条路线的前置条件。
