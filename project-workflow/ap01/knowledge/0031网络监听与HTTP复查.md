# 0031网络监听与HTTP复查

2026-10-11。使用SHA256为8a721fc8ef25458d415b2460e4a251e0503a82f7743fdff85b12612190e5c1cb的原厂文件，只读分析；无设备、无端口扫描、无米家登录。本轮服务更新设计见[Bridge接入设计第6节](../design.md)。

## 1. 当前结论

找到可定位的米家内部监听与两组HTTP客户端线索，尚未找到可直接追加业务路由的原厂局域网HTTP服务。不能将内核含socket/listen/accept实现、HTTP状态行字符串或米家服务存在单独视为HTTP服务端已启用。动态注册、间接调用及未覆盖代码段仍可能包含未定位服务。

## 2. 已确认的内部监听地址

0xa0065c7c..0xa0065c82设置参数(2,1,0)，调用0xa00267c4创建套接字；失败日志引用`Create ot server socket error`。0xa0065dfa..0xa0065e24填充16字节地址结构并调用0xa003f398。前8字节从常量0x32d40002、0x0100007f得到`02 00 d4 32 7f 00 00 01`，对应地址族2、网络字节序端口54322、127.0.0.1。错误日志又显式传入0xd432=54322，形成交叉核对。

0xa0065e68..0xa0065e6c调用0xa019f3ea；该封装在0xa019f40c设置积压数量32并调用0xa003c4ac。后者的断言引用`socket/listen.c`，再经套接字操作表间接调用底层监听。该调用关系支持存在实际内部监听路径，不只是无引用字符串。设备是否正在运行此分支仍需实机确认。

这里的127.0.0.1是AP01自身，不是电脑。这个绑定不会直接对局域网开放。现有证据未显示HTTP路由表或HTTP请求解析，不能把该内部入口当作浏览器接口。不要直接把绑定地址改为全部网卡；内部消息格式、身份边界和原厂依赖尚未查清。

同一区域另一条蓝牙相关监听路径以地址族1创建本地套接字，并使用长度0x6e的地址结构及路径字符串；日志复用了“port”字样，也不能因此判成另一个TCP端口。另有地址族0x10、类型3的内部网络事件套接字。上述仅用于识别原厂组件关系，不作为可调用接口承诺。

## 3. HTTP客户端证据

0xa0062c54..0xa0062c78将名称`httpc_task`、函数地址0xa01208b6及0x1400栈参数传给任务创建封装。创建封装的全部参数和生命周期未核实，不能直接照此启动新任务。

0xa0120f54..0xa0120f5c引用`GET %s HTTP/1.1`并把它交给带目标缓冲及剩余长度的格式化调用。0xa0121538..0xa012156a以28/15字节长度，将缓冲与`HTTP/1.1 206 Partial Content`、`HTTP/1.1 200 OK`交给0xa00500fe；该函数逐块/逐字节比较并返回差值。因此这两条状态行在此用于检查收到的响应，不是发送服务端成功响应的证据。

现有修改版已复用另一webclient入口0xa00d86ba取包；保留范围和上下文规则以[原厂定时任务机制与webclient上下文构造](https://github.com/andy-JustSayWhen/cuktech-ap01-firmware-tools/blob/3bd98a8ca4fb35a9f8869121b13961d405b16dff/knowledge/AP01-%E5%AE%98%E6%96%B9%E5%9B%BA%E4%BB%B6%E5%88%86%E6%9E%90/%E5%8E%9F%E5%8E%82%E5%AE%9A%E6%97%B6%E4%BB%BB%E5%8A%A1%E6%9C%BA%E5%88%B6%E4%B8%8Ewebclient%E4%B8%8A%E4%B8%8B%E6%96%87%E6%9E%84%E9%80%A0.md)为准。新的更新下载可优先研究该已用入口，不能混用上述米家httpc内部结构。看到206解析也不意味着现成支持任意断点续传，需核对请求参数和响应范围检查。

## 4. 扫描范围与原始证据

可打印ASCII字符串按至少6字节扫描；“server”初筛的6个命中全为httpdns前缀，包括httpdns enabled/disabled，均是误匹配，不能当httpd。协议关键词13项、一般网络关键词329项仅作定位。参考[字符串记录](../../../artifacts/ap01-research/raw/bridge-budget-20261011/http-service-strings.json)。

代码引用扫描覆盖文件0x1000..0x1b0000：先复用相邻指令地址匹配，再对选定高地址跟踪最多20条指令，遇目标寄存器覆盖、调用或分支停止，得到13条候选。随后人工检查监听和HTTP比较调用。此方法仍非完整控制流/数据流分析。任意窗口从中途开始可能截到前一条指令尾部，结论只使用经连续路径复核的有效指令。
